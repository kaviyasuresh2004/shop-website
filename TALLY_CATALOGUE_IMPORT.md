# Tally catalogue import

Administrator: sign in at `/staff`, open **Import Tally catalogue**, choose the prepared JSON and click **Import catalogue**. The BMK report is kept locally and is never committed or placed in public assets. The endpoint requires an administrator session, validates the destination shop and location, and imports transactionally. A private database backup is saved under the service volume's `backups` directory before a new import.

The October 15 BMK extraction contains every one of the 9,165 item names. Only Main Location quantities and prices are used. Missing Main Location entries, blank quantities and negative quantities create zero sellable stock. Missing prices remain zero and cannot be ordered. Original quantities and units appear in staff inventory. Fractional quantities are retained in the source reference with zero sellable stock until staff enter a corrected whole-number stock adjustment. This system currently sells whole units only.

An item appears in the public catalogue only with positive available stock, a positive price and no fractional-stock hold. The server also rejects orders for unavailable items. Staff can search the complete inventory by name or generated SKU, update prices and record stock adjustments; restocked products become visible on the next catalogue load. Identical file reuploads return the original receipt without resetting subsequent stock changes. A different report is a fresh stock snapshot, so reconcile online sales before applying one.

The importer generates stable identifiers from exact Tally item names; these are website identifiers, not inferred Tally stock codes. Renaming an item in Tally changes that identifier. Existing categories are retained on subsequent imports; new products start uncategorised. No product photos are inferred from names. Demo SKUs are set to zero available stock after import while their historical records remain intact. Users, orders and sales history are retained.
